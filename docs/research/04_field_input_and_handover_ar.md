# مدخلات الميدان (المهندس الطالب) + مذكرة Astra + ملفات DMP — تحليل وقرارات (2026-10-15)

## 1. ما قاله المهندس الذي طلب الأداة (منقول بالمعنى)
1. برنامج **Windows** يقرأ ملفات **datafile** من القرص.
2. "أوراكل يخزنها **مشفّرة** وتحتاج تفكّ التشفير".
3. الفرق عن أوراكل: أوراكل **يتوقف** عند البلوك الخربان؛ نحن **نصلح** ما يمكن، أو **نتخطى** ما انعدم.
4. في أسوأ الحالات **نخمّن** البيانات.
5. إذا ضاعت أسماء الجداول/الحقول نسحب البيانات كما هي و**نعطيها أسماء وهمية**.
6. اختبار: نزّل أوراكل، أتلف datafile بمحرر نص "خربش فيه من كل مكان".
7. الإصدار "مش مهم، كلهم تقريباً نفس الأسلوب، الفرق فقط الدوال بين 11 و12".

## 2. الحكم على كل نقطة
| # | الحكم | التفصيل | أثره على المشروع |
|---|---|---|---|
| 1 | ✅ مطابق | الأداة Windows-first من البداية (ADR-0001، بناء static CRT) | لا تغيير |
| 2 | ⚠️ **سوء فهم** | التخزين **صيغة ثنائية خاصة** (NUMBER بأساس 100، DATE بـ 7 بايت، ترميز الحروف…) وليس تشفيراً. التشفير الحقيقي فقط مع **TDE** (ميزة مدفوعة) ويحتاج wallet/مفاتيح العميل ولا يُكسر | نسأل كل عميل: هل TDE مفعّل؟ إن نعم ← نطلب الـ wallet (خارج النطاق الحالي) |
| 3 | ✅ مع تدقيق | صحيح أن القراءة العادية تتوقف (ORA-01578)، لكن لأوراكل أدوات (DBMS_REPAIR، RMAN BLOCKRECOVER، event 10231) — **كلها تحتاج قاعدة تعمل**. مجالنا: القاعدة لا تفتح أصلاً أو الملف وحده | **متطلب جديد REQ-004.1:** استخراج الصفوف السليمة من كتلة تالفة **جزئياً** (لا رفض الكتلة كلها) — الإصلاح في الذاكرة فقط، لا تعديل للملف (ADR-0002) |

| 5 | ✅ مطابق | هذه M4 (وضع بلا قاموس + استدلال) — الميزة الفارقة | أسماء وهمية ثابتة قابلة لإعادة الإنتاج: `OBJ_<objd>` و `COL_<n>` |

| 7 | ⚠️ نصف صحيح | تخطيط الكتلة والصف ثابت تقريباً منذ 8i ✅. لكن "الفرق فقط الدوال" **غير صحيح لنا**: الدوال تخص SQL ولا تؤثر على الملف. الفروق المؤثرة فعلاً في الجدول التالي | اختبار على 3 أجيال على الأقل |

### الفروق بين الإصدارات التي تؤثر على قراءة الملف (لا الدوال)
| الفرق | منذ | الأثر |
|---|---|---|
| CDB/PDB (قواعد داخل قاعدة) | 12c | قاموس وbootstrap$ لكل PDB؛ rdba نسبي (LV-026) |
| حجم رأس الملف kcvfh | 10g 676 ← 11g 860 ← 12c 1112 بايت | إزاحات الحقول بعد @140 تتغيّر (LV-028) |
| أعمدة جديدة في TAB$/COL$/OBJ$ | كل إصدار | مخطط القاموس يُقرأ من bootstrap$ نفسه، لا يُثبّت |
| ADD COLUMN بقيمة افتراضية دون كتابة الصفوف | 11g، توسّع 12c | الصف القديم لا يخزّن العمود (LV-023) |
| VARCHAR2 حتى 32767 (`MAX_STRING_SIZE=EXTENDED`) | 12c | تخزين كـ LOB داخلي |
| bigfile افتراضي لـ SYSTEM/SYSAUX/USERS | 23ai/26ai | rdba بلا رقم ملف (LV-031) |
| أنواع جديدة: BOOLEAN، JSON الأصلي، VECTOR | 21c/23ai | أنواع يجب التعرّف عليها أو وسمها غير مدعومة |

**قرار الإصدارات للمختبر:** (1) **Oracle Free (23ai/26ai)** للبدء لأنه متاح مجاناً بحاوية رسمية — مع إنشاء tablespaces **smallfile** صراحةً؛ (2) **19c** (الأكثر انتشاراً في الشركات، CDB)؛ (3) **11gR2 XE** (الأنظمة القديمة؛ ملفات DMP المستلمة من هذا الجيل).

## 3. مذكرة Astra (2026-10-15) — تقييم
**صحيح ومتّفق عليه:** الأولوية (صحة القيمة > العدد)، تصحيح "التشفير"، وجود DBMS_REPAIR/RMAN، "checksum سليم ≠ بيانات صحيحة" (اختبار إعادة حساب checksum بعد تعديل قيمة — **مُضاف لـ `odr-corrupt`: نمط `forge`**)، المختبر قبل التخمين، `dbv` مرجع مساعد لا حكم، مقاييس precision/recall/field-exactness بمقام صحيح، hold-out، Windows حقيقي لا cross-check فقط.

**مصادر مفيدة أضافتها (مُتحقق من وجودها):** DBCarver/CIDR 2017، DF-Toolkit/DB3F 2019، SoK DFRWS 2026، Oracle sample schemas (MIT)، Oracle Free الرسمي (Full مقابل Lite)، oracle/docker-images (19c/12c/11g XE).

**أخطاء/نواقص في المذكرة (مُصحّحة في `docs/handover/2026-10-15_handover.md`):**
1. حالة المستودع قديمة: #6 و#9 مغلقان؛ PR #10 **مراجَع بتعديلات مطلوبة** (B1–B4) لا "بانتظار المراجعة".
2. المختبر هو العائق الحاسم لكن بلا مسار تنفيذ: لا Docker عند أي وكيل ← الحل `lab/` على جهاز المالك أو VPS.
3. 26ai وحده خطر: bigfile افتراضي (نفس العيب الذي كسر S1a) ← smallfile صريح + 19c/11g.
4. نزع الأولوية العربية بحجة "أداة عامة" غير مقبول: AR8MSWIN1256 ميزة فارقة وتبقى في كل مجموعة اختبار.

## 4. ملفات DMP المستلمة — ماذا تعني
- 4 ملفات `.DMP` بترويسة `EXPORT:V11.01.00` = **Original Export** (`exp`) من جيل 11g — **ليست Data Pump** (`expdp` ترويسته مختلفة)، و**ليست DBF**.
- **لاختبار ODR:** تُستورد بـ `imp` (لا `impdp`) في مختبر 11g/19c معزول ← DBF حقيقي ببيانات محاسبية عربية ← عيّنة خاصة. تنبيه: الاستيراد يعيد بناء التخزين، فالـ DBF الناتج يمثّل إصدار المختبر لا إصدار المصدر.
- **فرصة منتج (M8 مقترح، لا يُبدأ الآن):** ملفات `exp` التالفة شائعة جداً (نسخ احتياطية ليلية مقطوعة/تالفة) و`imp` يتوقف عند أول خطأ. صيغة `exp` موثّقة جزئياً ومُعاد هندستها علناً (نصوص DDL + صفوف بأطوال). أداة تستخرج ما يمكن من DMP تالف = منتج ثانٍ بنفس النواة (types/charset/value).
- **خصوصية:** لا يُرفع أي منها أو من ناتجها إلى git أو Releases أو أي corpus عام؛ لا يُشغّل أي PL/SQL/trigger/job منها خارج مختبر معزول.

## 5. متطلبات جديدة ناتجة (تُضاف إلى REQ-004)
- **REQ-004.1** استخراج الصفوف السليمة من كتلة تالفة جزئياً (ترويسة سليمة + دليل صفوف جزئي، أو صفوف سليمة بعد منطقة تالفة)، كل صف يُتحقق منه بنيوياً وبنوع أعمدته.
- **REQ-004.2** عند فقد القاموس: أسماء وهمية حتمية `OBJ_<objd>` / `COL_<n>` وتوصيف المخطط المستنتج.
- **REQ-004.3** المخرجات ثلاث طبقات منفصلة: `verified/` (يمر كل الفحوص)، `inferred/` (مستنتج مع درجة ثقة ومصدر)، `rejected/` (ما لم يُفك مع السبب والبايتات الخام). لا تُخلط أبداً.
- **REQ-004.4** تقرير لكل ملف: كل كتلة وحالتها، كل صف ومصدره (Provenance)، SHA-256 للدليل قبل/بعد.

## 6. أسئلة لكل عميل (قائمة ثابتة)
1. إصدار Oracle و`COMPATIBLE`؟ 2. هل TDE مفعّل؟ 3. `NLS_CHARACTERSET` و`NLS_NCHAR_CHARACTERSET`؟ 4. الملفات على قرص عادي أم ASM؟ 5. حجم الكتلة؟ 6. هل يوجد SYSTEM سليم؟ 7. هل تتوفر نسخة سابقة (حتى لو قديمة) أو DMP؟ 8. نوع التلف (فدية؟ قرص؟ انقطاع كهرباء؟ حذف؟)
