# 0005 — معيار الجودة الهندسية (غير قابل للتفاوض)
## السياق والمشكلة
الأداة ستُسلَّم لشركة (يمن سوفت) تستخدمها على بيانات عملاء محاسبية حقيقية، ويعمل عليها 4 مطوّرين (وكيل مدير + 3 وكلاء) بالتوازي. بلا معيار آلي موحّد تتباين الجودة ويتسلل الخطأ الصامت.
## القرار — كل ما يلي يُفرض آلياً في CI، لا بالمراجعة فقط
**أمان المدخلات**
- `unsafe_code = "forbid"` على مستوى الـ workspace.
- Clippy: `indexing_slicing`, `unwrap_used`, `panic` = **deny**؛ `pedantic` + `arithmetic_side_effects` = warn ← وCI يعامل كل warn كخطأ (`-D warnings`). كل `#[allow]` يحمل تعليقاً يبرر لماذا هو آمن.
- كل محلّل بنية جديدة = هدف `cargo fuzz` + اختبار خاصية (proptest) "لا ينهار على أي بايتات".
**صحة البيانات**
- لا `f32/f64` لتمثيل NUMBER أبداً؛ التمثيل دقيق (عشري نصي/أرقام base-100).
- المُفكِّك يرفض الترميز الذي لا ينتجه أوراكل (مثل NUMBER غير مُطبَّع) بدل أن يخمّن.
- كل ثابت بنيوي مأخوذ من مصدر يُوسم بمرجعه، وما لم يُتحقق منه على ملفات المختبر يُوسم `lab-verify`.
- اختبار يحتوي على متجهات معروفة (`DUMP()` من أوراكل) لكل نوع بيانات.
**الأداء**
- لا تحميل ملف كامل في الذاكرة في المسار الإنتاجي؛ القراءة بالتدفق/mmap.
- أي PR يمسّ المسار الحرج يرفق قياس criterion قبل/بعد على نفس الجهاز.
**المنصات**
- CI على `windows-latest` و`ubuntu-latest`؛ Windows هو المنصة الأساسية للعميل.
- لا مسارات أو فواصل أسطر خاصة بنظام؛ `std::path` فقط؛ دعم المسارات الطويلة وأسماء عربية في Windows.
**الاعتماديات والترخيص**
- `cargo deny`: يرفض أي ترخيص copyleft (GPL/AGPL/LGPL/MPL) وأي مصدر غير crates.io، وأي ثغرة معروفة.
- اعتمادية جديدة تحتاج تبريراً في الـ PR (الحجم، الصيانة، الترخيص).
**التوثيق**
- `missing_docs` + `cargo doc -D warnings`: كل عنصر عام موثّق، وكل وحدة تبدأ بشرح البنية الثنائية ومصادرها.
**Git**
- Conventional Commits؛ PR صغير مركّز؛ لا دمج دون CI أخضر ومراجعة المدير.
