# 0006 — العمل بعدة وكلاء على مستودع واحد
## السياق والمشكلة
وكيل مدير + 3 وكلاء بنماذج مختلفة يبنون بالتوازي. الخطر: تعارضات دمج، تغيير عقود مشتركة دون علم الآخرين، تكرار عمل، وتباين أسلوب.
## الخيارات
1. كل وكيل حر في أي ملف 2. **ملكية وحدات + عقود مجمّدة + فرع لكل وكيل + المدير هو الوحيد الذي يدمج**
## القرار
الخيار 2:
- **الملكية** (`.github/CODEOWNERS` و`docs/agents/README.md`): كل وحدة لها مالك واحد يكتب فيها. التعديل خارج ملكيتك = PR صغير منفصل يوسم المالك.
- **العقود المجمّدة** (يملكها المدير): `bytes.rs`، `error.rs`، `block.rs`، `source.rs`، والأنواع العامة في `scan.rs` و`row/mod.rs`. تغييرها يتطلب ADR أو موافقة المدير في issue.
- **الفروع**: `agent/a-scanner`، `agent/b-rows-types`، `agent/c-lab-bench`؛ فروع فرعية `agent/a-scanner/<feature>` مسموحة. PR نحو `main` فقط.
- **الإيقاع**: كل وكيل يعمل `git fetch && git rebase origin/main` قبل كل PR؛ PR لكل مهمة مستقلة (لا PR عملاق).
- **التواصل**: قسم "قيد العمل" في `STATUS.md` يحدّثه كل وكيل بسطر واحد (اسمه، المهمة، الفرع)؛ الأسئلة على العقود = issue يوسم المدير.
- **الدمج**: المدير يراجع ويدمج بـ "Create a merge commit" بعد CI أخضر.
## العواقب
- ✔ تعارضات شبه معدومة؛ كل وكيل يعمل بأقصى سرعة في منطقته.
- ✘ المدير نقطة اختناق في المراجعة؛ تخفيف: PRs صغيرة وCI صارم يجعل المراجعة سريعة.

## تعديل 2026-10-15 — وكيلان بدل أربعة (قرار المالك)
- **Lead** (المدير، يعمل أيضاً): العقود + طبقة الصفوف والأنواع والترميز والقاموس والاستدلال + المراجعة والدمج.
- **Astra** (GPT Astra): المسح والأداء وCLI + المختبر والملفات الذهبية + القياس والـ fuzzing وCI.
- الفروع: `lead/<feature>` و`agent/astra[/<feature>]`. حُذفت `agent/a-scanner` و`agent/b-rows-types` و`agent/c-lab-bench`.
- مبدأ إضافي: **من يكتب المفكّك لا يصنع الحقيقة التي يُقاس عليها** (Lead يفكّ، Astra يُخرج الملفات الذهبية).
- مراجعة متبادلة: PRs الـ Lead يراجعها المالك أو Astra.
